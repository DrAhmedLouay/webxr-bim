## 🗺️ تكامل الواقع المعزز (AR)

خارطة الطريق التفصيلية لتكامل AR (المحور الثاني) — المراحل، معمارية الطبقات، سير العمل
الميداني، مصفوفة الاختبار، والمخاطر:

**📄 [AR_ROADMAP.md](AR_ROADMAP.md)**

المنفَّذ حالياً: دخول AR أصلي (`immersive-ar` + `dom-overlay`)، دخول VR أصلي
(`immersive-vr`)، تصدير GLB صالح (glTF 2.0)، مُولِّد علامات ارتساء QR مستقل بالكامل،
فلترة الطوابق، وتصدير BCF / PDF / CSV.

### الميزات الجديدة
| الميزة | الملف | الوصف |
|---|---|---|
| **الجسر بين VR/AR** | `js/model-store.js` | مخزن IndexedDB مشترك: المنصة تحفظ النموذج المحمّل، و`ar.html` تستعيده عبر `?modelKey=` — والعلامة NFT تحمل هذا الرابط مباشرة |
| **صفحة AR مستقلة** | `ar.html` | صفحة للهاتف: جلسة `immersive-ar` + `hit-test` + تثبيت النموذج بمقياس 1:1 على السطح الحقيقي |
| **تصدير BCF 2.1 حقيقي** | `js/bcf.js` | أرشيف `.bcf` مطابق لمرجع buildingSMART (bcf.version + project.bcfp + markup.bcf + Viewpoint .bcfv) |
| **موصّل BIMcollab / BCF-API** | `js/bcf.js` | اختبار اتصال، جلب المشاريع، سحب المواضيع، دفع التعارضات (BCF-API 2.1) |
| **استضافة النموذج (Google Drive وغيره)** | `ar.html` + `js/model-store.js` | روابط Drive تُحوَّل تلقائياً إلى رابط تنزيل مباشر، مع سلسلة بدائل وتشخيص دقيق للأخطاء |
| **نشر النموذج على GitHub** | `js/github-publisher.js` | رفع GLB/IFC إلى `models/` في أي مستودع عبر رمز PAT محدود الصلاحية — الرابط الناتج على `raw.githubusercontent.com` يعمل من أي جهاز (يدعم CORS) |
| **تطبيق ميداني PWA** | `manifest.json` + `sw.js` | قابل للتثبيت على الهاتف ويعمل دون اتصال (تم التحقق بتحميل كامل مع انقطاع الشبكة) |

## ☁️ استضافة نموذج الـ AR (Google Drive وغيرها)

حقل **«🔗 رابط النموذج المباشر»** في نافذة مُولِّد علامة NFT هو ما يجعل العلامة تعمل على **أي جهاز**.
ما يجب وضعه فيه:

| الخيار | القيمة | ملاحظات |
|---|---|---|
| **Google Drive** | رابط المشاركة كما هو | يُحوَّل تلقائياً إلى `drive.usercontent.google.com/download?id=…&export=download` — **يجب** أن يكون الملف بصلاحية «أي شخص لديه الرابط» |
| **Drive عبر وسيط** | `https://script.google.com/macros/s/<ID>/exec?fileId=<DRIVE_ID>` | وسيط Apps Script (المصدر في `tools/gdrive-proxy/Code.gs`) — يلزم «Anyone» عند النشر |
| **GitHub Pages (نفس المستودع)** | `models/tower-a.glb` (مسار نسبي) | الأسهل: نفس النطاق ⇒ لا مشاكل CORS — ضع الملف في مجلد `models/` |
| **أي استضافة** | `https://host/path/model.glb` | يجب أن تسمح بالقراءة من نطاق آخر (CORS) |
| **شبكة الموقع** | `http://192.168.x.x:8000/model.glb` | للاستخدام الميداني دون إنترنت، عبر خادم محلي |

### نشر وسيط Google Drive (Apps Script)
1. <https://script.google.com> ← مشروع جديد
2. الصق محتوى `tools/gdrive-proxy/Code.gs`
3. `Deploy ▸ New deployment ▸ Web app` — «Execute as: Me» — «Who has access: **Anyone**»
4. انسخ رابط النشر `https://script.google.com/macros/s/<ID>/exec`
5. استخدمه هكذا: `…/exec?fileId=<DRIVE_FILE_ID>`

### أخطاء الاستضافة الشائعة (يعرضها `ar.html` تلقائياً)
| الرسالة | السبب | الحل |
|---|---|---|
| `المضيف يرفض الطلبات من نطاق آخر (CORS)` | الخادم لا ي发送 `Access-Control-Allow-Origin` | استضافة أخرى، أو وسيط Apps Script |
| `أعاد الخادم صفحة HTML بدل ملف النموذج` | Drive يعرض شاشة تأكيد病毒/حجم للملفات الكبيرة | رابط مباشر أو الوسيط |
| `خطأ HTTP 403/404` | الملف غير مشارك أو الرابط خاطئ | تفعيل «أي شخص لديه الرابط» |
| `وسيط Drive ردّ بخطأ` | الوسيط لم يجد الملف | تحقق من `fileId` وصلاحية المشاركة |

## 🐙 نشر النموذج إلى GitHub (من داخل المنصة)

زر **«🐙 نشر النموذج على GitHub»** يرفع الملف المحمّل (GLB/IFC) إلى مجلد `models/` داخل
مستودع تختاره، ثم يعطيك رابطاً **يعمل من أي جهاز** — لأن `raw.githubusercontent.com`
يرسل `access-control-allow-origin: *`، بخلاف أصول Releases التي لا تسمح بالقراءة
من نطاق آخر.

> ⚠️ **لا تُدخل كلمة مرور GitHub.** ألغت GitHub مصادقة كلمة المرور في الـAPI منذ 2020،
> وطلب كلمة مرور داخل نموذج ويب سلوك غير آمن. استخدم **Personal Access Token**.

### إنشاء الرمز
1. <https://github.com/settings/personal-access-tokens/new> (Personal Access Token *fine-grained*)
2. Repository access: اختر **مستودعاً واحداً فقط**
3. Permissions → **Contents: Read and write**
4. أنشئ الرمز وانسخه (`github_pat_…`)

### الاستخدام
| الخطوة | التفاصيل |
|---|---|
| 1 | استورد GLB/IFC في المنصة (يُحفظ في `ModelStore`) |
| 2 | افتح «🐙 نشر النموذج على GitHub» والصق الرمز ← «تحقّق» (يعرض الحساب والصلاحيات) |
| 3 | اختر المستودع والفرع والمسار (افتراضياً `models/<اسم الملف>`) |
| 4 | «⬆️ رفع النموذج» ← يظهر رابط `raw.githubusercontent.com/...` |
| 5 | «🔗 استخدامه في علامة NFT» ← تُملأ رابط العلامة تلقائياً |
| 6 | اطبع العلامة → المسح بالهاتف يفتح `ar.html?model=<raw url>` ← المجسم يُحمَّل من GitHub |

### حدود وحدود بديلة
| الحد | القيمة | البديل |
|---|---|---|
| حجم الملف | ‎50 MB‎ (Contents API) | زر «📋 نسخ أمر curl» (يعمل مع `GITHUB_TOKEN` من الطرفية بلا رمز في المتصفح) |
| حد GitHub الفعلي | 100 MB للملف | Git LFS أو مستودع خاص + رابط موقّع |
| نوع المستودع | عام | الرابط `raw` يعمل للمستودع العام فقط؛ الخاص يحتاج توكن |

### أمان
- الرمز يُحفظ في **sessionStorage** فقط (يُمسح بإغلاق التبويب) — وليس `localStorage`.
- زر «نسيان الرمز» يمسحه فوراً.
- المنصة **لا ترسل الرمز** إلى أي جهة خارجية غير `api.github.com`.
